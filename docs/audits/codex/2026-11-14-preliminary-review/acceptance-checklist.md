# Проверки после сообщения о завершении

Проверки ещё не проводились; все пункты не отмечены. Это программа будущей приёмки, а не результаты тестирования. Размер 16×16 подтверждён пользователем 14 ноября 2026 года.

## По заданию пользователя

- [ ] В PowerShell на чистом пользовательском окружении с поддерживаемой версией Node.js команда из README получает пакет и открывает приложение в браузере. Проверить именно распространяемый пакет, а не только запуск из исходников.
- [ ] Ссылка на GitHub доступна студентам; пакет содержит необходимые файлы приложения и примеры. Готовность локальной сборки и доступность публичного распространения зафиксировать отдельно.
- [ ] Поставляется около 100 изображений 16×16, по десять на цифру. Проверить файлы, метки, различия начертания и шум.
- [ ] На основном экране есть выбор изображения слева, сеть в центре и вертикальный список 1, 2, 3, 4, 5, 6, 7, 8, 9, 0 справа.
- [ ] Новая сессия начинает учебный сценарий; ручная метка и исправление ошибки действительно меняют параметры сети.
- [ ] После обучения режим распознавания вычисляет ответ по пикселям изображения. Переименование одинакового файла не меняет ответ; метка из manifest не подменяет предсказание.
- [ ] Схема соответствует вычисляемой сети. Все заявленные связи доступны для просмотра; подсветка и численные значения получены из текущего прохода. Веса связей, смещения и активации обозначены раздельно и понятно.
- [ ] Полный сценарий занятия воспроизводится: исходное состояние, обучение, исправление ошибки, распознавание. Название курса, подписи и значения читаются на экране преподавателя.

## Дополнительные проверки рецензента

- [ ] Измерить результат отдельно на обучающих примерах, отложенной части и новых изображениях. Не считать точность на знакомых примерах доказательством обобщения. Проходной порог точности пользователь не задавал.
- [ ] Проверить пустое, повреждённое и неподходящее изображение, а также понятность сообщений об ошибке.
- [ ] Проверить повторный запуск, сброс, сохранение и восстановление модели, если эти возможности заявлены разработчиком.
- [ ] Проверить работу после установки без интернета, область прослушивания локального сервера и ограничения раздачи файлов. Это дополнительные проверки, а не новые требования пользователя.
- [ ] Сопоставить результаты штатных тестов с независимыми сценариями и сохранить команды, версии, наблюдения и ограничения в новом отчёте.

## Как фиксировать итог

Новый отчёт сохранить в отдельной датированной папке внутри `docs/audits/codex/`. Для каждого существенного замечания указать воспроизведение, ожидаемое и фактическое поведение, место в коде и влияние на занятие. Повторную проверку исправлений связать с исходным замечанием; предыдущие результаты сохранить.
