# Требования пользователя и задание исполнителю

Дата фиксации: 14 ноября 2026 года. Проект: `neural-network-digit-recognition`. Это задание на следующий этап, а не заявление о реализации. Состояние текущей версии описано в [аудите](README.md), проверка изменений выполняется по [чек-листу приёмки](acceptance-checklist.md).

## Назначение и исходные условия

Приложение предназначено для курса «Искусственный интеллект для инженеров». Преподаватель показывает его на своём компьютере, студенты получают исходники на GitHub и запускают приложение одной командой через npm/npx. Внутри приложения доступны примеры изображений и средства обучения сети.

Действующий размер изображения **16×16**. Первоначальные 36×36 отменены прямым уточнением пользователя. Требуется три смысловые области: изображение слева, нейросеть и связи в центре, цифры `1, 2, 3, 4, 5, 6, 7, 8, 9, 0` вертикально справа. Встроенный набор: примерно 100 примеров, по десять вариантов каждой цифры, с вариациями написания и шумом. В проверенной версии есть 80 обучающих и 20 проверочных примеров.

Веса, активации и результаты должны соответствовать реальному вычислению. Вес связи и активацию нейрона нужно подписывать разными понятиями. Видимость всех связей не должна мешать чтению выбранного пути и его чисел. Качество на небольшом синтетическом наборе нельзя выдавать за гарантированное распознавание любого почерка.

## R-01. Рисование, распознавание и обратная связь преподавателя

Согласованный пользователем сценарий режима «Обучение»:

1. Пользователь рисует цифру на Canvas. Введённое изображение сохраняется на экране.
2. Нажимает «Распознать». Появляются предсказание, вероятности и анимация связей именно этого входа.
3. Если ответ верный, нажимает явно названную кнопку подтверждения, например **«Верно, обучить на цифре 5»**. Это одно осознанное действие обучения на показанной цифре.
4. Если ответ неверный, выбирает правильную цифру щелчком по соответствующему выходному нейрону. Выбор также должен быть доступен с клавиатуры: это дополнительный критерий доступности из аудита. Выбор по правой строке цифры предлагается как удобная альтернатива.
5. Появляется карточка или окно: **«Правильная цифра: 7. Использовать для обучения?»**, кнопки **«Да, обучить»** и **«Отмена»**. Выбранный целевой класс явно подсвечен.
6. До подтверждения веса и счётчик шагов не меняются. После подтверждения выполняется ровно один шаг с выбранной меткой, а не с прежним значением списка или с предсказанием сети.
7. Рисунок не очищается. Интерфейс сообщает, какая метка использована, и показывает изменение результата. Повторный расчёт и его анимация явно обозначены как состояние после обучения.

Список «Правильный ответ» может остаться альтернативным доступным способом выбора, но он должен быть синхронизирован с выбором выходной цифры. Выбор нейрона для исследования его параметров и выбор правильной метки должны различаться. Возможный вариант: в режиме обучения щелчок по выходу выбирает ответ, а отдельная кнопка «Посмотреть параметры» или наведение открывает инспектор. В режиме распознавания щелчок только исследует нейрон.

Обработку двойного подтверждения нужно защитить: пока шаг выполняется, повторный клик не должен создавать второй шаг. Смена рисунка, файла или модели отменяет неподтверждённый ответ для прежнего входа. Проверочный встроенный пример нельзя незаметно включать в обучение и продолжать учитывать как независимый validation.

**Текущее состояние:** щелчок по выходному кружку меняет только инспектор. Правильная метка берётся из отдельного списка. Браузерная проба: после щелчка по верхнему выходу инспектор показал класс 0, список сохранил 5; последующее обучение повысило вероятность 5 с 13,7% до 46,7%. [Доказательство](evidence/browser/output-click-result.json), [экран](evidence/browser/15-output-click-does-not-label.png). Подпись самого кружка дополнительно ошибочна, см. AUD-01.

## R-02. Продолжающаяся анимация после распознавания

Прямое уточнение пользователя: после «Распознать» связи должны продолжать красиво переливаться до выбора следующей картинки; новый вход должен получать визуализацию своего расчёта. Короткого исчезающего эффекта недостаточно.

Задача исполнителю:

- После распознавания запускать повторяющееся движение импульсов и плавное изменение яркости на связях текущего результата. Не завершать эффект через фиксированные 850 мс.
- Строить интенсивность и выделение из фактических вкладов `w × a`, сохраняя различие положительного и отрицательного веса. Случайная декоративная смена связей не подходит.
- В полносвязной сети вычисление использует все связи. Если анимируется только наиболее заметная часть, прямо подписать: «Выделены наиболее сильные вклады; в расчёте участвуют все связи».
- При смене входа убирать прежнюю анимацию и устаревший ответ. Следующее «Распознать» запускает визуализацию нового результата. При изменении весов также нельзя оставлять эффект, рассчитанный для прежней модели.
- Предусмотреть «Пауза / Продолжить», скорость и статическое выделение при `prefers-reduced-motion`. Использовать плавное свечение и движение, а не резкие вспышки. Не запускать несколько параллельных циклов от повторного нажатия.
- Подписать смысл: «Повторная визуализация прямого прохода». Само мерцание не обучает сеть и не меняет вероятности.

**Текущее состояние:** короткий эффект есть; непрерывного нет. В браузере ранние кадры различаются, кадры примерно через 1,31 и 1,71 с совпадают по SHA256. В коде длительность ограничена 850 мс. [Проба и времена](evidence/browser/animation-timing.json).

Пауза здесь предлагается как средство управления демонстрацией. [WCAG 2.2, пояснение 2.2.2](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide.html) также рассматривает контроль движущегося контента; обязательность конкретного пункта зависит в том числе от способа запуска, поэтому сам факт анимации после намеренного нажатия не объявляется нарушением.

## R-03. Понятный режим преподавателя

Нужен сценарий, который позволяет остановиться на одном примере и объяснить: пиксели, взвешенную сумму, смещение, активацию, вероятности, ошибку, градиент и изменение веса. Рекомендация аудита: отдельные действия «Следующий шаг», «Пауза», «Быстро обучить»; значения `w_old`, `gradient`, `η`, `Δw`, `w_new` для выбранной связи; история loss и accuracy по эпохам.

Крупные числа выбранного нейрона и органы управления должны быть доступны без попытки читать подписи 6–8 CSSpx. Для проекторного вида предложены сворачиваемая галерея, закреплённые кнопки и схема выбранного пути. Полный граф и таблица всех весов остаются доступны как подробный вид. Это варианты реализации, а не результат испытания с реальными студентами.

## R-04. Разделение обучения и распознавания

В «Распознавании» ни выбор примера, ни щелчок по нейрону, ни анимация, ни кнопки не меняют веса, смещения и steps. Обучающие действия доступны только после явного перехода в «Обучение». Все подписи, инспектор, крупный ответ и таблица относятся к одному входу и одной версии модели.

## R-05. Обязательные Git, GitHub и оформление выпуска

Это обязательная часть задания исполнителю, а не необязательное улучшение.

1. Создать локальный Git-репозиторий и зафиксировать исходники, тесты, данные, документацию и `docs/audits/codex/`. Аудиты нельзя терять при дальнейших изменениях.
2. Оформить репозиторий на GitHub под согласованной учётной записью, дать фактическую доступную студентам ссылку. Наличие удалённого репозитория проверяется открытием ссылки, а не упоминанием в тексте.
3. README уже существует. Довести его до состояния фактического выпуска: назначение курса, требования к Node.js, рабочая команда npx с фиксированной версией, установка и остановка в PowerShell, запуск из исходников, сценарий R-01, анимация R-02, примеры экранов, обучение и проверка, импорт/экспорт/сброс, ограничения качества, устранение типовых проблем, тесты и ссылки на аудиты.
4. Проверить `.gitignore` и состав коммита/пакета: без npm-cache, `node_modules`, временных профилей браузера, секретов и результатов служебных процессов. Сохраняемые доказательства аудита должны быть включены намеренно.
5. Проверить MIT LICENSE, версию и метаданные package.json: `repository`, `homepage`, `bugs`, `bin`, `files`, `engines`, описание и фактический лицензионный статус данных. Не выдумывать автора или владельца npm scope.
6. Вести CHANGELOG или равноценные release notes, связывающие исправления с AUD-ID и R-ID. Выпустить согласованную версию npm из проверенного пакета; окончательное имя и scope должны принадлежать владельцу.
7. Проверить обещанную команду на чистом окружении: устанавливается нужный пакет и версия, открывается браузер, доступны все примеры, приложение можно остановить. Проверка владельца пакета предшествует его исполнению.

На момент аудита локальная упаковка работает, публичный npm registry возвращает E404, локального Git-репозитория нет. README честно относит публикацию к будущему действию. Аудит не выполнял публикацию, git init, commit или push.

## R-06. Сохранение требований и повторная проверка

Все проверки Codex сохраняются в `docs/audits/codex/`, в датированных подпапках. Старые отчёты остаются историей. Исполнитель отмечает для каждого AUD-ID/R-ID, что изменено, где находится исправление и какая проверка выполнена. Собственное сообщение «готово» не закрывает пункт: после него выполняется независимая повторная приёмка.
