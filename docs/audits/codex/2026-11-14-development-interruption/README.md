# Остановка Kimi Code после чтения PNG

Дата: 14 ноября 2026 года. Статус: отказ воспроизведён на конкретном файле; исходная рабочая сессия не восстановлена.

Kimi Code получает HTTP 400 при передаче `public/samples/digit-5-00.png` модели. Ошибка повторилась в новых диагностических сессиях. Текстовый запрос и чтение большого скриншота приложения завершились успешно.

## Подтверждённые факты

- В исходной сессии первый отказ произошёл 14 ноября в 20:13:11 CET, сразу после ReadMediaFile для digit-5-00.png. По состоянию журнала на 20:28:14 CET зафиксировано 19 одинаковых отказов, включая 18 повторов после первого; последний в 20:26:27 CET.
- Ответ провайдера: HTTP 400, `provider.api_error`, `APIStatusError`, `Invalid request Error`. Поле retryable имеет значение false.
- Файл имеет размер 231 байт, размеры 16×16 и режим PNG grayscale (L). Проверка структуры через Pillow Image.verify() прошла. Это не гарантирует совместимость со всеми обработчиками изображений.
- При воспроизведении использованы Kimi Code Desktop 1.3.3, локальный сервер 2.5.2, модель `kimi-code/k3.1-pro`, effort `max`.
- SHA256 проверенного PNG: `1e2d2af7124d9208c787fb347a4f08271ee9315502b96b5663a4d729a201b1cd`.

## Контрольные запросы

| Условие | Результат |
| --- | --- |
| Новая сессия, только текст, та же модель и effort | Успех, ответ TEXT_OK |
| Новая сессия, ReadMediaFile для точной копии PNG 16×16 | Следующий запрос к модели завершился HTTP 400 |
| Ещё одна новая сессия, тот же PNG прямым вложением | Первый запрос завершился HTTP 400 |
| Сессия текстового контроля, ReadMediaFile для скриншота приложения 2000×1124 | Успех, модель описала интерфейс |

Прямое вложение отказало при оценке контекста 7260 токенов в локальном журнале. Большая история исходного диалога не является необходимым условием воспроизведённой ошибки.

Первая проба через отдельный профиль CLI 2.1.1 не проверяла передачу изображения: в профиле отсутствовал ReadMediaFile, а текстовый Read отказался читать PNG. Эта проба не засчитана как воспроизведение.

## Объяснение и границы вывода

Изолированные проверки связывают отказ с передачей конкретного PNG модели. Они не устанавливают точный внутренний дефект провайдера: причиной могут быть размер, цветовой режим или другая особенность обработки файла. Сообщение API не содержит такой детализации. Утверждение «все изображения 16×16 не поддерживаются» не подтверждено.

Повторное использование истории с этим изображением согласуется с наблюдаемыми отказами Continue. В официальном репозитории Kimi опубликован похожий случай после ReadMediaFile: [issue 4863](https://github.com/MoonshotAI/kimi-code/issues/4863). Это сообщение другого пользователя о сходном сбое, а не доказательство точного совпадения внутренней причины.

[Справочник ошибок Kimi](https://www.kimi.com/code/docs/en/kimi-code/error-reference.html) относит HTTP 400 к ошибкам содержимого запроса. В текущих журналах нет сообщения об исчерпании квоты или неверном ключе; успешные контрольные запросы подтверждают работоспособность доступа к модели во время проверки.

## Продолжение разработки

Рекомендованный обход: новая сессия в том же каталоге проекта с передачей текущего плана и сохранённых файлов. Для визуального просмотра примеров использовать скриншот интерфейса: этот путь проверен. Учебные PNG оставить размером 16×16, как согласовано в задании.

[Текст передачи работы в новую сессию](recovery-handoff.md) подготовлен отдельно. Он не отправлялся в рабочую сессию разработчика. Продолжение разработки после перехода в новый диалог ещё не проверено.

Исходная история, настройки Kimi, исходники приложения и учебные PNG в ходе этой диагностики не редактировались. Созданы только диагностические сессии, копии файлов и материалы проверки. Сырой журнал с содержимым диалога и локальные учётные данные в репозиторий не включены.
